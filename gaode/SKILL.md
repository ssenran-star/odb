# 周边去哪儿：基于高德的地点推荐助手

## 名称、用途与适用场景

- **名称**：gaode-nearby-recommend（周边去哪儿）
- **用途**：完成一次「提出需求 → 查询高德 → 返回推荐」：理解需求、查询真实地点、筛出符合条件的候选，并给出可信的步行到达信息。
- **适用场景**：例如「我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。」
- **非目标**：不写多站行程、不做设备定位、不依赖长期记忆/多轮/跨城市/PowerMem/seekdb。

## 硬性约束

1. 只使用评测平台提供的**高德 MCP Server**工具；不要填写或硬编码 API Key。
2. 必须使用的两类能力：
   - **地点搜索**（优先**周边搜索**：keywords + location，可选 radius）
   - **步行路径规划**（origin + destination → 步行距离与预计耗时）
3. 最多推荐 **3** 个；不足可少推并说明原因。
4. 每个推荐必须含：名称、地址、预计步行距离与时间、一句推荐理由。
5. **步行距离与时间必须来自步行路径规划**，禁止用直线距离、经验估算或「距离测量」工具替代。
6. 各地点是同一起点的**独立备选**，不要串成 A→B→C 行程。
7. 明确违反硬条件（如步行超时、类型不符）的地点，**不能**列为符合条件的推荐。
8. 安静程度、排队、营业状态等缺少工具依据的信息：标注「未核实」，禁止编造。
9. 查询失败或无符合结果：如实说明，可建议放宽条件；不要编造地点和路线。
10. 评测会给出明确起点坐标，不必实现设备定位。

## 任务流程（引导 Agent）

### 1. 理解需求

从输入中解析（输入含城市、起点、自然语言需求）：

| 字段 | 说明 |
|------|------|
| city | 城市（若有） |
| origin | 起点经纬度（评测直接给出；若只有地址，先地理编码再搜） |
| place_type / keywords | 地点类型，如咖啡馆、餐厅、公园 |
| walk_limit | 步行时间或距离上限（如 ≤15 分钟） |
| max_n | 推荐数量，默认且上限为 3 |
| sort_pref | 排序偏好，如「优先近一点」 |

把硬约束与软偏好分开：硬约束用于过滤，软偏好用于排序与理由。

### 2. 地点搜索

1. 调用**周边搜索**：`keywords` = 需求类型，`location` = 起点坐标；若有步行上限，先用较小 `radius` 试探，结果不足再适度放大。
2. 结果仍不足时，可用**关键词搜索**（带 city）补充，但最终仍须用步行路线判断是否达标。
3. 需要更完整地址/类型时，对候选做**详情搜索**（POI id）。
4. 记录候选：名称、地址、坐标、类型（以工具返回为准）。类型必须与需求一致（要咖啡馆不能拿餐厅充数）。

### 3. 步行路线规划与筛选

对每个仍保留的候选，调用**步行路径规划**：

- origin = 用户起点
- destination = 该地点坐标

只采用返回的步行 `distance` / `duration`（或 paths 中等价字段）。

然后筛选：

- 有步行上限：剔除超时/超距候选
- 「优先近一点」：按步行时间（或距离）升序
- 截断为最多 3 个

### 4. 生成回答

用**列表或表格**呈现；简洁、可帮助用户做选择。

#### 有推荐时

```text
推荐（共 N 个｜起点：…｜需求：…）：

| # | 名称 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
|---|------|------|----------|----------|----------|
| 1 | … | … | … 米 | … 分钟 | … |
| 2 | … | … | … 米 | … 分钟 | … |

说明：步行数据来自高德步行路径规划。
备注：…（如有「未核实」项写这里）
```

也可用同等信息量的列表，但四要素不能少。

#### 结果不足时

```text
符合条件的推荐共 N 个（少于请求的 M 个）。
原因：查询范围内符合「…」且步行 ≤… 的地点不足。
建议：可放宽步行时间 / 扩大范围 / 更换关键词。
（下列为已找到的 N 个，格式同上。）
```

#### 无结果或工具失败时

```text
未能给出推荐。
原因：未找到符合条件的地点 / 高德工具调用失败或异常（简述）。
已尝试：周边搜索关键词「…」、半径…、并对 N 个候选做了步行校验。
建议：放宽条件后重试。
```

## 评测场景自检

给出最终答案前检查：

- [ ] 普通推荐：≤3，地点真实，类型符合
- [ ] 时间限制：没有把超时地点算作符合条件
- [ ] 偏好排序：顺序与解释和路线数据一致
- [ ] 不足/异常：如实说明，无编造
- [ ] 每个结果都有名称、地址、步行距离、步行时间、一句理由
- [ ] 无 API Key；无直线距离冒充步行

## 工具对照（名称以评测环境实际 MCP 工具名为准）

| 能力 | 典型输入 | 典型输出 |
|------|----------|----------|
| 周边搜索 | keywords, location, radius? | pois |
| 关键词搜索（补充） | keywords, city? | pois |
| 详情搜索（可选） | poi id | 地址、类型、坐标等 |
| 步行路径规划 | origin, destination | paths / distance / duration |
| 地理编码（仅起点是地址时） | address, city? | location |

本题必做链路是：**地点搜索 → 步行路径规划 → 筛选 → 列表/表格回答**。
